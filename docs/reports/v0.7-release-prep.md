## Push policy

Not pushed. `release/v0.1.0` through `release/v0.6.0` all exist on the
remote, but in every prior version's history the release-branch commit
("Prepare vX.Y.0 GitHub release") was the same commit that immediately
preceded the actual tag/npm-publish/GitHub-Release/merge sequence - there
is no prior precedent in this repository for a distinct, separately-gated
"release prep produced but not yet published" remote branch state (no
`docs/reports/*-release-prep.md` exists for any earlier version; this is
the first time that separate stage exists at all). Per this task's own
default ("do not push unless established precedent explicitly requires
it") and the absence of such precedent, `release/v0.7.0` was kept local
only. Pushing it, opening a PR, tagging, and publishing all remain part of
the separate, later, explicitly-approved publication workflow.
