## ROADMAP and CLI/help audit

ROADMAP now correctly says v0.8.1 is implemented in the repository, package
metadata remains `0.8.0`, and publication has not happened. v0.9 and v0.10
remain future work; the v0.9 alias/canonical-identity invariant and v0.10
reuse of `check <baseline> --json` are explicit.

Built CLI help was captured under the prerelease audit root for every public
command. The common surface is `init`, `capture`, `check`, `view`; advanced
commands remain `observe`, `compare`, `approve-baseline`,
`save-change-contract`, `evaluate-contract`, `import-reference`,
`approve-reference`, and `evaluate-reference-fidelity`. Documentation now
states that `view` discovers initialized project evidence without `--root`,
while `view --root` remains the standalone compatibility form.

Documentation records check exits exactly as PASS 0, FAIL 1,
REVIEW_REQUIRED 2, BLOCKED 3. Comparison alone is evidence and yields
REVIEW_REQUIRED, never PASS. JSON is documented as a bounded ephemeral
workflow projection rather than a persisted artifact.

## Architecture and code-rot audit

Direct source tracing found one canonical semantic owner for browser
observation (`observationPersistence`), comparison (`comparisonEngine`),
frontend-contract evaluation (`frontendContractEvaluation`), reference
compatibility, explicit binding, reference fidelity, bounded context,
runtime/static correlation, discovery, catalog persistence, project-check
orchestration, and check-result projection. `projectCheckService` composes
those owners; it neither spawns the CLI nor adds an evaluation engine.

The packed check helper that duplicated the viewer/project workflow was
removed. `runPackedViewerSmoke.mjs` is now the single installed-package
project/viewer smoke owner and covers REVIEW_REQUIRED plus unchanged-criteria
FAIL-to-PASS before alias-aware viewer checks. `runPackedObservationSmoke.mjs`
retains its lower-level legacy responsibility. Windows npm installation in
both smoke owners invokes npm's CLI through Node with `shell: false`; no
project-controlled value is shell command text.

Historical release reports and frozen plans retain their older descriptions as
historical evidence. Current-state documentation no longer presents v0.8.1 as
merely planned or `view --root` as universally required.

## Security and package truth

The audit reconfirmed portable acceptance paths, realpath/junction containment,
alias/catalog containment, immutable `current` replacement, project-relative
JSON, approved-reference-only governance, explicit bindings, loopback/read-only
viewer routing, media traversal containment, and PWA no-stale-evidence tests.
The dynamic-execution search found `spawn` only in controlled viewer opening
and CI/developer smoke infrastructure; production project/config/evidence
inputs do not become executable command text. A real-Chromium source-hash test
proves `capture`, `check`, and `view` do not modify target frontend source.

`npm pack --dry-run --json` is audited in Phase B. Package metadata remains
`0.8.0`; v0.8.1 is implemented in source but not released, tagged, or
published. CHANGELOG remains release history and has no released v0.8.1 entry.
