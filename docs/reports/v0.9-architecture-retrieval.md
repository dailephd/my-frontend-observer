### Persistence pattern

All established artifact writers validate before writing, derive a final
directory from the fresh instance ID, refuse an existing final directory, write
to a sibling `.tmp-<id>` directory, write `manifest.json` (and observation
media where owned), then atomically rename the temporary directory. On failure,
the temporary directory is removed. Readers parse and structurally validate the
manifest; they do not silently coerce unsupported versions.

## 5. Existing viewer-server architecture

- Startup/application seam: `src/viewerServer/viewerService.ts#startViewer`.
  It validates the root, selects built assets via `defaultViewerAssetsRoot`,
  passes session-only bindings/context/alias metadata into
  `createViewerServer`, and listens only on `127.0.0.1` using
  `src/viewerServer/port.ts`.
- HTTP routing: `src/viewerServer/httpServer.ts#handleRequest`.
  Only `GET` and `HEAD` are accepted; other methods receive `405` and
  `Allow: GET, HEAD`. The server serves status/index/artifact/media APIs,
  relationship, comparison, evaluation, reference, candidate, binding, and
  fidelity/context routes, plus the static viewer shell.
- Evidence discovery/indexing: `src/viewerServer/evidence/discovery.ts#discoverManifests`
  finds bounded `manifest.json` files; `evidence/index.ts#buildEvidenceIndexMetadata`
  rebuilds metadata on every request, limits records, classifies, and projects
  metadata. `loadArtifactByHandle` performs on-demand full loading and
  revalidation.
- Classification: `src/viewerServer/evidence/classify.ts#classifyManifest`.
  Supported families are observation, comparison, baseline contract, change
  contract, contract evaluation, imported external reference, and approved
  external reference. It dispatches to the canonical reader for each family;
  the reader remains the structural authority. New persisted families are not
  discovered automatically: classification requires an explicit kind/version
  branch, reader, and family projection.
- Handles and containment: `evidence/handles.ts` creates/decodes opaque
  evidence-relative handles; `evidence/pathSafety.ts#resolveContainedDir` and
  `resolveContainedFile` fail closed on traversal, separators, NULs, and
  absolute escape. `mediaResolver.ts#resolveMedia` restricts roles and uses
  `lstat` to reject non-regular files and symlink-like escapes.
- Media resolution: `evidence/mediaResolver.ts#resolveMedia` resolves
  observation `screenshot`, imported-reference `image`, and approved-reference
  `source-image`. Approved source image resolution uses the canonical logical
  `referenceId` to rediscover the imported artifact; it does not treat a stored
  path as provenance.
- Observation relationship route: `httpServer.ts` dispatches
  `/api/observations/:handle/relationships` to
  `evidence/observationView.ts#getObservationRelationships`, which invokes the
  canonical relationship derivation once for the selected observation.
- Comparison/evaluation routes: `/api/comparisons/:handle/view` and
  `/api/evaluations/:handle/view` dispatch to `comparisonView.ts` and
  `evaluationView.ts`. They resolve canonical artifacts and linked evidence;
  they do not recompute comparison or contract evaluation in the browser.
- Reference route: `/api/references/:handle/view` dispatches to
  `referenceView.ts#getReferenceView`, which invokes exactly the canonical
  `deriveReferenceRegionRelationships` and
  `deriveReferenceRequirementAdequacy` functions over persisted regions and
  requirements. These results are ephemeral projections, not persisted.
- Candidate route: `/api/references/:reference/candidate/:candidate/view`
  invokes canonical compatibility and coordinate/fidelity support in
  `referenceView.ts`; it also discovers referenced evaluation handles.
- Binding route: `/api/references/:reference/candidate/:candidate/bindings`
  invokes `isValidReferenceRuntimeBindingDeclarations` and
  `evaluateReferenceRuntimeBindings` using startup-supplied session input.
- Fidelity route: `/api/references/:reference/candidate/:candidate/fidelity`
  invokes `getReferenceFidelity`, which uses the canonical
  `deriveCoordinateScale` and `evaluateReferenceCandidateFidelity` path.
- Context route: `src/viewerServer/context.ts` classifies a supplied
  bounded-agent-context artifact at startup; the viewer does not rebuild it.

The one-canonical-engine rule is visible in these server call sites: the
viewer server may resolve, call, and project supplied evidence, but it is not a
second relationship, compatibility, binding, fidelity, bounded-context, or
runtime/static-correlation engine. Viewer routes are read-only and session
bindings/context are not persisted.

## 6. Runtime screenshot coordinate architecture

- `viewer/src/components/ObservationWorkspace.tsx#ObservationWorkspace` owns
  presentation selection (`selected`), overlay toggles, ordered targets, the
  screenshot media URL, and the relationship hook. Selection resets when the
  artifact handle changes.
- `viewer/src/observation/targetOrder.ts#orderedTargets` owns deterministic
  target ordering.
- `viewer/src/components/TargetOverlaySvg.tsx#TargetOverlaySvg` renders the
  screenshot and target geometry. Its `viewBox` is
  `0 0 requestConfig.viewport.width requestConfig.viewport.height`; the
  viewport is the captured CSS-pixel frame. The `<image>` fills that frame and
  target `geometry.x/y/width/height` is used unchanged.
- No `devicePixelRatio` multiplication, rounding, or clamping is performed.
  Out-of-frame geometry remains evidence and is only clipped by SVG display
  overflow. Missing/partial geometry does not receive a fabricated rectangle.
- Selection and highlighting are UI-only props: `selected` drives
  `aria-pressed` and the selected class; optional `highlightNames` is a visual
  secondary emphasis. Click and Enter/Space keyboard handlers call `onSelect`.
- `viewer/src/hooks/useZoomPan.ts#useZoomPan` owns presentation zoom/pan. It
  uses scale `1..8`, step `1.25`, derives viewBox from frame dimensions and
  focal point, resets uncontrolled state on frame changes, and maps pointer
  coordinates with `getScreenCTM().inverse()`. Pan begins only after a 3-screen-
  pixel drag threshold; focal points clamp to the frame. `ZoomPanBinding` is a
  rendering-only subset passed to the SVG leaf.

Closest protection is `tests/browser/observationSvgWorkspace.test.ts`, covering

## 7. External-reference coordinate architecture

- `src/domain/externalReferenceRegions.ts#ReferenceRegion` is the canonical
  authored region: `{id, rectangle:{x,y,width,height}}`.
- Reference coordinates are reference-image pixels, origin at the image
  top-left, with fractional values permitted. They are never CSS pixels.
  `isValidReferenceRegionRectangle` rejects non-finite, negative, or nonpositive
  values; `isValidReferenceRegions` bounds count, deduplicates IDs
  case-insensitively, and rejects rectangles outside image dimensions. Derived
  right/bottom/centers are recomputed, not persisted.
- `viewer/src/components/ReferenceWorkspace.tsx#ReferenceWorkspace` owns
  selected region, candidate handle/target selection, overlay toggles,
  optional evaluation selection, explicit binding highlights, and view lock.
  It resets presentation state when the reference handle changes.
- `viewer/src/components/ReferenceRegionOverlaySvg.tsx#ReferenceRegionOverlaySvg`
  uses `viewBox="0 0 imageWidth imageHeight"`, renders the reference image at
  those dimensions, and renders `region.rectangle` unchanged. Its IDs are
  `data-region-id` values and are not runtime target names.
- The reference overlay has separate `requirementRegionIds` and
  `highlightRegionIds` presentation props. A bound cross-selection highlights
  the other domain without changing that domain's primary interactive
  selection.
- Reference and runtime views share the `useZoomPan` interaction machinery,
  but each supplies its own frame dimensions and SVG coordinate domain.
  `deriveCoordinateScale` in `src/domain/externalReferenceFidelity.ts` is the
  canonical cross-domain mapping used by fidelity evaluation; it is not a
  reason to merge region identity with target identity.

## 8. Reference-region / requirement / binding / fidelity architecture

- Regions are explicit user/configuration input carried in imported and approved
  external-reference artifacts. Rectangle geometry is persisted; derived
  geometry and region relationships are not.
- Region relationships are derived by
  `src/domain/externalReferenceRegionRelationships.ts#deriveReferenceRegionRelationships`.
- Requirements are explicit design intent over regions. Their domain is
  `src/domain/externalReferenceRequirements.ts`; requirement identity is in
  `externalReferenceRequirementIdentity.ts`, and adequacy is derived by
  `deriveReferenceRequirementAdequacy`. Requirement categories reuse
  `AuthoredChangeScopeCategory`; `unexpected` cannot be authored.
- Applicability is explicit external-reference input owned by
  `src/domain/externalReferenceApplicability.ts` and participates in reference
  identity. It is not inferred by the viewer.
- Bindings are session/configuration input owned by
  `src/domain/externalReferenceRuntimeBinding.ts`. The viewer startup receives
  declarations, validates/evaluates them per selected pair, and does not
  persist them. Binding identity is therefore not an artifact identity.
- Compatibility is derived by `externalReferenceCompatibility.ts`.
- Coordinate scale and fidelity are derived by
  `externalReferenceFidelity.ts`; fidelity is not the same as compatibility,
  adequacy, or binding status.
- Imported and approved reference artifacts are persisted; region relationships,
  adequacy, compatibility, binding evaluation, coordinate mapping, and fidelity
  are derived on demand or evaluation-artifact output, depending on workflow.
- `externalReferencePersistenceService.ts` validates and persists authored
  regions/requirements/applicability as part of import/approval. Approval carries
  these fields forward from imported evidence; it does not mutate the prior
  artifact.

  accept arbitrary new persisted families without explicit classification and
  reader branches.

## 11. Persistence/lifecycle precedents

- Observation, comparison, contract, evaluation, and external-reference writers
  use immutable per-instance directories, sibling temporary directories, atomic
  rename, no-overwrite checks, and cleanup on failure.
- Request/logical identity is deterministic from canonical semantic content;
  instance identity is fresh and opaque. Timestamps are not used as the sole
  instance identity.
- External reference import and approval support an explicit `supersedes`
  reference. `externalReferencePersistenceService.ts` reads the superseded
  artifact to resolve its logical ID, while the writer writes a new artifact.
- Contract baseline approval preserves an authored `supersedesBaselineId` and
  never mutates or removes the prior baseline. Evaluation preserves source
  references and creates a fresh `evaluationId`.
- Alias replacement updates the alias catalog only; previous canonical artifact
  directories remain unchanged.
- There is no current forward-pointer mutation in artifact manifests beyond
  explicit supersession/reference fields, and no writer silently replaces prior
  evidence.

## 14. Planner-relevant constraints

- `ReferenceRegionOverlaySvg` and `TargetOverlaySvg` intentionally use separate
  coordinate domains. Reference-region identity is not runtime-target identity.
- Runtime target geometry is captured/rendered in viewport CSS pixels without
  device-pixel-ratio conversion, rounding, or clamping.
- The viewer is GET/HEAD-only, loopback-only, read-only, metadata-first, and
  must not become an evidence or domain derivation engine.
- Evidence discovery currently requires explicit artifact-family classification
  and canonical reader dispatch; arbitrary new manifests are reported as
  unrecognized rather than auto-supported.
- Canonical readers remain the sole structural validation authority at the
  viewer boundary.
- Viewer derivation call sites are explicit: observation relationships in
  `observationView.ts`, reference relationships/adequacy and pair computations
  in `referenceView.ts`, and route dispatch in `httpServer.ts`.
- Bindings and bounded context are session input. They are read once by startup,
  not persisted or browser-selected by file path.
- Aliases select canonical artifact directories and never provide artifact
  provenance or replace canonical IDs.
- Artifact persistence is immutable by precedent: fresh instance directory,
