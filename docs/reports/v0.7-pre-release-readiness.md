## Security validation

`npm run test:security` (68/68 passed) plus source/test inspection of v0.7
security-sensitive surfaces:

- **External image file input**: format/dimension detection reads only
  bounded header bytes (`externalReferenceImage.ts`), never decodes pixel
  data; malformed/truncated/oversized inputs are rejected with structured
  diagnostics (`externalReferenceImage.test.ts`).
- **Region/requirements/applicability config input**: all three CLI file
  loaders (`loadRegionsFile`/`loadRequirementsFile`/`loadApplicabilityFile`)
  own only root-shape/JSON-parse syntax; every content rule (bounds, id
  patterns, category/tolerance/subject validity) is owned by the domain
  validators they call into, covered by
  `externalReferenceRegions.test.ts`/`externalReferenceRequirements.test.ts`/
  `externalReferenceApplicability.test.ts`.
- **State-file input**: `loadStateFile` is root-shape-only; label pattern and
  `authenticatedState` enum are enforced by `isValidExplicitStateDimensions`
  (`explicitState.test.ts`). The state vocabulary is explicitly documented as
  never a place for credentials/tokens/cookies/session ids.
- **Bindings file**: `loadBindingsFile` is root-shape-only; every bound-region
  existence/uniqueness/pattern rule is owned by
  `isValidReferenceRuntimeBindingDeclarations`
  (`externalReferenceRuntimeBinding.test.ts`).
- **Path traversal / operational-path privacy**: the extended smoke itself
  re-verifies (as the pre-existing v0.4/v0.5/v0.6 sections already did) that
  no operational absolute filesystem path (consumer dir, artifact roots,
  config file paths) leaks into any persisted manifest, across the new v0.7
  calls too.
- **No credential-bearing explicit-state data**: confirmed by the
  `ExplicitStateDimensions`/`ExternalReferenceApplicability` closed field
  vocabularies (`theme`/`applicationState`/`authenticatedState`/`viewport`
  only) — no field exists for tokens/cookies/headers.
- **Reference/observation artifact immutability**: the extended smoke
  re-hashes the pre-existing baseline observation manifest after running all
  new v0.7 CLI/programmatic calls and confirms it is byte-identical.
- **No external AI/network upload**: `referenceCorrectionWorkflow.ts`'s own
  module doc explicitly states it "never calls a remote AI provider"; grep of
  `src/` confirms no `fetch`/network client exists outside the browser
  automation and observer's own disposable local HTTP fixture use in tests.
- **No observer source editing**: `prepareReferenceCorrection`/
  `reviewReferenceCorrectionAttempt` are pure, synchronous, in-memory
  functions with no filesystem write capability — they return structured
  results only; source-editing is explicitly the external actor's own
  separate responsibility per the module's documented contract.

No security failure, resolved or unresolved, was found.
