## 6. select-option contract

The released action used is:

```json
{
  "type": "select-option",
  "locator": { "kind": "role", "role": "combobox", "name": "Intent category" },
  "value": "requested"
}
```

It maps to Playwright's `Locator.selectOption({ value })` and verifies that
exactly the requested value was selected. v0.4.9 supports `value` only. The
closed validator rejects `label`, `index`, `values` and multi-select arrays, so
none of those are used.

## 10. Readiness contract-reader root cause

`scripts/run-v09-tutorial-readiness.mjs` used one helper for every canonical
reader:

```js
async function readArtifact(reader, file) {
  const result = await reader(file);
  if (!result?.ok) fail(...);
  return result.artifact;
}
```

That is correct for `readVisualAnnotationArtifact` and
`readExternalReferenceArtifact`, whose success result is `{ ok: true, artifact }`.

It is wrong for the canonical frontend-contract readers. Their success results
are:

- `readPersistentBaselineContract` returns `{ ok: true, contract }`
- `readPerChangeContract` returns `{ ok: true, contract }`

Neither returns `artifact`. The script therefore pushed `undefined` for every
valid contract, and the later `item.contractClass` evaluation threw
`Cannot read properties of undefined (reading 'contractClass')`. This is why the
Windows and Ubuntu jobs failed after otherwise running the tutorials.

Reproduced against the three real contract manifests written by a local
scenario 2 run:

All three returned `undefined` from the old helper, and evaluating
`contractClass` on that value threw
`Cannot read properties of undefined (reading 'contractClass')`. The fixed
reader returned a defined contract for each:

1. the per-change contract promoted by the tutorial: `change`
2. `tutorial-baseline/v09-tutorial-baseline`: `baseline`
3. `tutorial-initial-change/v09-tutorial-initial-change`: `change`

- `CONTRACTCLASS_CRASH_REPRODUCIBLE_BEFORE_FIX`: true
- `CONTRACTCLASS_CRASH_CLOSED`: true

## 11. Contract-reader correction

A dedicated canonical contract reader was added. No optional-chaining
workaround was used, no raw JSON was parsed to choose a reader, and no third
contract validator was introduced:

```js
async function readContract(file) {
  const baseline = await readPersistentBaselineContract(file);
  if (baseline.ok) return baseline.contract;
  const change = await readPerChangeContract(file);
  if (change.ok) return change.contract;
  fail(`canonical contract readers rejected ${file}: baseline=${baseline.reason}; change=${change.reason}`);
}
```

Trying each canonical validator is what decides the contract class, so the raw
`contractClass` dispatch was removed. `jsonFile()` became unused and was
deleted, along with the now-unused `readFile` import. A later-unused `sha256()`
helper was also removed. `BASELINE_READER_RESULT_PROPERTY` and
`CHANGE_READER_RESULT_PROPERTY` are both `contract`.

## 12. Two further readiness verifier defects found while proving the fix

Once the `contractClass` crash was closed, the local run reached scenario 3 and
scenario 4 evidence checks for the first time. Both were broken in the same
family as the contract-reader defect: the script read canonical artifacts
through a shape that does not exist.

### 12.1 Reference lifecycle compared as a string

The script used `item.lifecycle === 'approved'` and
`item.lifecycle === 'imported'`. The canonical contract in
`src/domain/externalReference.ts` is:

```ts
export interface ImportedExternalReferenceArtifact extends ExternalReferenceArtifactBase {
  lifecycle: { state: 'imported' };
  image: ExternalReferenceImageReference;
}
export interface ApprovedExternalReferenceArtifact extends ExternalReferenceArtifactBase {
  lifecycle: { state: 'approved'; approvedAt: string };
  sourceReference: ExternalReferenceSourceReference;
}
```

`lifecycle` is an object, so both comparisons were always false and scenario 3
could never pass. Verified against real evidence: both references reported
`oldStringCompareWorks: false`.

This was never reached in run `35527166495` because Windows and Ubuntu crashed
in scenario 2 and macOS failed in scenario 2.

Corrected to use the canonical exported type guards
`isApprovedExternalReferenceArtifact` and `isImportedExternalReferenceArtifact`
rather than a locally re-derived check.

### 12.2 The materialized image digest comparison never executed

The scenario 4 check was:

```js
const imagePath = (reference) => reference.image?.path ? path.join(...) : undefined;
const sourceImage = imagePath(approved);
const revisionImage = imagePath(imported[0]);
if (sourceImage && revisionImage && sha256(...) !== sha256(...)) fail(...);
```

An approved artifact has no top-level `image`; it carries
`sourceReference.image`. `sourceImage` was therefore always `undefined`, and the
`sourceImage && revisionImage` guard made the comparison a silent no-op. The
check reported success while proving nothing, which is exactly the
absent-evidence-as-PASS failure the evidence-honesty rules forbid. Verified
against real evidence: the approved artifact reported `hasTopLevelImage: false`.

Corrected to compare the canonical identity-bearing digests directly, with no
file re-hashing and no filesystem path construction:

- source: `approved.sourceReference.image.sha256`
- materialized: the successor's `image.sha256`

A missing digest on either side now fails explicitly instead of being skipped.

### 12.3 Imported-reference count assumption

The scenario 4 check also required exactly one imported reference. Real
evidence shows a materialization target holds three references: the original
source import, the approval, and the materialized successor. So
`imported.length !== 1` would have failed even after the lifecycle fix.

The successor is now identified by the property that actually distinguishes it,
namely that it carries requirements, while the reference the approval came from
carries none. Observed: `importedCount: 2`, `materializedCount: 1`,
`digestsMatch: true`.

### 12.4 Diagnosability

The scenario 3 and scenario 4 checks previously collapsed several distinct
conditions into one generic message such as
`reference authoring invariants failed`. Each condition now fails with its own
message naming the actual cause and the observed counts.
