## 5. Annotation metadata projection

For a supported annotation, `buildMetadataRecord` returns:

1. `logicalId`: `annotationId`
2. `schemaVersion` and `producerVersion` from the artifact
3. `annotationSourceKind`: `source.kind`
4. `annotationItemCount`: `items.length`
5. `annotationConfirmedItemCount`: the number of items whose interpretation
   state is `confirmed`
6. `media`: one `annotation-overlay` summary (a cheap availability check only)
7. `relatedIds`: `sourceObservationId` or `sourceReferenceId`, plus
   `supersedesAnnotationId` when present

Items are never embedded in metadata. Observation alias metadata is applied
only to observation records, so an annotation record never gets an alias.

   overlay cannot run script in the viewer origin, where the authoring token

## 9. Authoring session capability

1. New `src/viewerServer/authoringSecurity.ts` defines:
   1. `VIEWER_AUTHORING_TOKEN_BYTES = 32`
   2. `VIEWER_AUTHORING_TOKEN_HEADER = 'x-frontend-observer-authoring-token'`
   3. `MAX_ANNOTATION_AUTHORING_BODY_BYTES = 256 * 1024`
2. One token is created per authoring server session with
   `randomBytes(32).toString('hex')`, which gives 64 lowercase hex characters.
   It lives only in the in-memory `ViewerAuthoringSession`
   `{ projectRoot, token, expectedHost, expectedOrigin }`. It is never
   persisted, never put in a cookie, storage, a URL, a cache, or an artifact,
   and never logged.
3. `expectedHost` and `expectedOrigin` are set after the listener binds to its
   actual port. They are `127.0.0.1:<port>` and `http://127.0.0.1:<port>`.
   Before that they are empty strings, and an empty expectation matches
   nothing.
4. `GET` and `HEAD` `/api/authoring/session` always send `cache-control: no-store`:
   1. A read-only viewer returns `{ ok: true, enabled: false }`.
   2. An authoring viewer returns `{ ok: true, enabled: true, token }` and
      nothing else.
5. Defense in depth (additional local decision): in authoring mode the session
   route returns 403 unless the `Host` header equals `expectedHost`. This keeps
   the token away from a DNS-rebinding page.

## 10. POST security policy

`POST /api/annotations` runs these checks in order:

1. Authoring disabled gives 403.
2. `Host` must equal `expectedHost`, else 403.
3. `Origin` must equal `expectedOrigin` exactly, else 403. A missing Origin is
   also 403.
4. The token header must match exactly, else 403. The comparison uses
   `timingSafeEqual` when lengths match, and the response does not say which
   part differed.
5. `Content-Type` must be `application/json`, optionally with a UTF-8 charset,
   compared case-insensitively. Anything else gives 415.
6. `Content-Encoding` present and not `identity` gives 415.
7. A declared `Content-Length` above 262144 gives 413 before any body is read.
   An undeclared chunked body stops being collected once it passes 262144
   bytes and also gives 413. Rejections send `connection: close`, so the
   server stops receiving further body bytes.
8. Malformed JSON gives 400.
9. Unknown top-level request fields give 400.

Method policy:

1. `POST` is accepted only for `/api/annotations`. `GET` or `HEAD` on that path
   returns 405 with `Allow: POST`.
2. `POST` on any other path returns 405 with `Allow: GET, HEAD`. This includes
   the Prompt 5 and Prompt 6 route names, which do not exist.
3. `PUT`, `PATCH`, and `DELETE` return 405 everywhere.
4. No CORS headers are sent.

2. Observation: the source is built exactly as the prompt specifies. The

3. Imported reference: built from `referenceId` and `image.sha256`, `width`,

4. Approved reference: built from `sourceReference.referenceId` and
   `sourceReference.image`.
5. An alias is never used as source identity.

## 14. Revision and stale-edit behavior

1. With no parent, `supersedesAnnotationId` is undefined.
2. With a parent, the parent is resolved through `loadArtifactByHandle` and
   must be `visual-annotation`.
   1. Unknown gives 404.
   2. Not an annotation, or not loadable, gives 409.
3. `isSameVisualAnnotationSource` compares every canonical source field for
   each source kind. A mismatch gives 409. It is a pure local helper and is
   not exported from the package.
4. Stale check: a bounded scan (`discoverManifests`, `MAX_INDEX_RECORDS`,
   `classifyManifest`) looks for any supported annotation whose
   `supersedesAnnotationId` equals the parent id.
   1. Any such child gives 409, including when several children exist.
   2. No child is ever selected by timestamp.
5. Local decision: if discovery was truncated, the lineage cannot be proven
   free of children. The save fails closed with 409 instead of silently
   branching.
6. Local decision: saves are serialized per authoring session with an
   in-process promise queue. The stale check and the write cannot interleave.
   A test sends three concurrent revisions of one parent and gets exactly one
   201 and two 409s.
7. The parent artifact is never modified.

## 15. HTTP status behavior

1. 201: a save succeeded.
2. 400: malformed JSON, invalid request shape, an unknown top-level field, a
   malformed view or media handle, or an invalid Content-Length.
3. 403: authoring disabled, or a Host, Origin, or token failure. Also the
   session route on an unexpected Host.
4. 404: unknown source handle, unknown parent handle, unknown view or media
   handle, or a rejected media role or file.
5. 405: an unsupported method or route combination.
6. 409: source not loadable or not annotatable, parent not an annotation,
   parent source mismatch, parent already has a child, lineage unverifiable,
   or a view handle that is not a loadable annotation.
7. 413: body over 262144 bytes.
8. 415: wrong content type or a compressed body.
9. 422: canonical annotation validation failure, such as out-of-frame
   geometry or a cross-domain item.
10. 500: persistence failure, returned with a generic message and no stack
    trace or path.
