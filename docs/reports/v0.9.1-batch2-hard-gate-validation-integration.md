## 4. Root cause carried forward

1. `OLD_READINESS_PREDICATE`: `(await navigator.serviceWorker.getRegistration())?.active !== undefined`
2. `OLD_ACTIVE_VALUE_AT_FAILURE`: `null` (the worker was still installing)
3. `OLD_CLIENT_CONTROLLER_AT_FAILURE`: `null`
4. `WHY_OLD_PREDICATE_PASSED`: `null !== undefined` is `true`. The check passed
   as soon as a registration existed, before activation or control. The server
   then closed too early. The precache held only 5 entries, and the reload
   failed with `net::ERR_CONNECTION_REFUSED`.
5. `CORRECT_ACTIVE_PROOF`: `registration.active !== null`, read from
   `await navigator.serviceWorker.ready`
6. `CURRENT_CLIENT_CONTROL_PROOF`: `navigator.serviceWorker.controller !== null`

Shared state hid the bug in normal order. Earlier tests in the same describe
block had already activated a controlling worker on the same server origin.
Selected alone, the server starts on a new random port, so no worker existed yet
for that origin.

Classification remains `TEST_DEFECT`. No product defect was found.
