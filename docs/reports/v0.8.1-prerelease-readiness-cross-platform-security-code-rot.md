## 4. Documentation/completeness and architecture audits

The companion
`v0.8.1-implementation-completeness-documentation-reconciliation.md` report
passes the bidirectional capability matrix. It found one CI-readiness/code-rot
defect: v0.8.1 packed `check` proof was isolated in a separate helper rather
than the established packed viewer owner. The helper was removed and
`runPackedViewerSmoke.mjs` now proves installed `init`, `capture baseline`,
`check --json` REVIEW_REQUIRED, unchanged-contract FAIL-to-PASS, `baseline`
and `current` aliases, canonical-ID detail, and the viewer. The lower-level
packed observation smoke remains separate by responsibility.

Source tracing confirms one semantic owner each for browser observation,
relationships, comparison, contract evaluation, reference compatibility,
explicit binding, reference fidelity, bounded context, runtime/static
correlation, discovery, catalog persistence, project-check orchestration, and
check projection. `check` only composes canonical owners and creates no
persisted check artifact or second evaluation engine.

## 7. Security and code-rot audit

Project discovery stops at the nearest config. Alias/catalog validation and
atomic catalog persistence are fail-closed. Acceptance paths are portable and
realpath-contained; a Windows junction escape is rejected by real browser
coverage. `current` replacement changes catalog metadata only and preserves
canonical history. Check JSON uses project-relative paths, bounded collections,
and no image bytes. Imported references are not approved authority; bindings
remain explicit; contract FAIL cannot be overridden by reference PASS.

Viewer security regressions cover loopback binding, read-only methods,
traversal/media containment, symlink/junction containment, and no stale PWA
evidence. Production source has no eval/new-Function/vm execution. The only
process spawns are controlled viewer opening and development/CI smoke tooling;
Windows packed npm invocation uses Node's npm CLI with `shell: false`.
