## 4. The three independent root causes

The earlier compressed summary attributed the whole failure to tutorial
portability. That was incomplete.

1. Candidate/package job: failed in `npm test` because one scenario pause was
   too short. `02-runtime-intent-contract.json/category-requested` declared
   `pauseAfterMs` of `10900` where the frozen readability rule required
   `11900`. The exact candidate tarball was therefore never built, so the
   package matrix was `NOT_REACHED`.
2. Windows tutorial job: the readiness verifier crashed with
   `Cannot read properties of undefined (reading 'contractClass')` because
   contract-reader success results were extracted through the wrong property.
3. Ubuntu tutorial job: the same readiness verifier crash.
4. macOS tutorial job: scenario 2 failed while using native-select keyboard
   emulation.

This was an Observer tutorial pacing fixture defect, an Observer readiness
verifier bug, and a generic my-dev-kit-lab native-select portability gap. No
core Observer product regression was established by that run.

Two further readiness verifier defects, both in the same family as the second
root cause, were found while proving the correction locally. They were
unreachable before, because every earlier run died in scenario 2. Both are
recorded in `docs/reports/v0.9-final-readiness-corrections.md`.

## 6. The readiness verifier correction

The canonical frontend-contract readers return `contract`, not `artifact`. The
verifier now reads contracts through a dedicated canonical helper that tries
`readPersistentBaselineContract` and then `readPerChangeContract`, and fails
with both validation reasons. No raw JSON is parsed to choose a reader and no
third contract validator exists.

The reference checks now use the canonical exported type guards
`isApprovedExternalReferenceArtifact` and `isImportedExternalReferenceArtifact`
instead of comparing `lifecycle` as a string, and the materialized image digest
is compared through the artifacts' own identity-bearing `sha256` fields, which
means that comparison actually executes rather than being silently skipped.

## 7. The pacing correction

The frozen rule is unchanged and was not weakened:

```
readingMs = max(1200, ceil((narration.length / 15) * 10) * 100)
```

Every step in all four scenarios was re-paced after the narration edits. All
210 steps satisfy the rule. The candidate job proved this remotely by getting
past `npm test`.
