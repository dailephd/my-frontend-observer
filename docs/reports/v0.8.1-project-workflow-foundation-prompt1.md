## 3. Implementation

New ownership modules are `src/projectWorkflow/projectConfig.ts`, `projectDiscovery.ts`, `projectPaths.ts`, `aliasCatalog.ts`, and `src/application/projectWorkflowService.ts`.

The project configuration schema is `1.0.0` with exactly `schemaVersion`, `url`, `viewport`, `targets`, and `defaultBaseline`. It reuses `RawNamedTarget` and validates URL, viewport, targets, locators, and output safety through `normalizeRequest()` with `.frontend-observer/evidence/_validation`. The default baseline is `baseline`.

Aliases use exactly `^[a-z0-9][a-z0-9._-]{0,63}$`; traversal-like double-dot values are rejected and `current` is reserved. Catalog schema `1.0.0` maps aliases to canonical observation ID, request ID, and POSIX evidence-relative artifact directory. Readers fail closed. Writers serialize schema first, sort aliases, use two-space indentation and a trailing newline, write a sibling temporary file, and rename only after completion.

Discovery walks upward from a resolved directory to the filesystem root and stops at the nearest `frontend-observer.json`. Managed paths are centrally derived for configuration, `.frontend-observer`, catalog, evidence, and observation output.

`init` shares the existing viewport, CSS target, and structured target-file parsing owners. It creates configuration, catalog, and evidence state and inserts exactly one `.frontend-observer/` ignore entry. `--replace` replaces configuration only.

`capture <alias>` discovers the project, validates configuration and catalog, normalizes one canonical observation request, calls `observe()` once with `{ cwd: projectRoot }`, and updates the alias only after persistence. Replacement leaves old evidence intact; failed replacement leaves the old mapping intact.

`view` without `--root` discovers and validates project state, uses the managed evidence root, and supplies an in-memory exact-relative-directory alias map. Explicit `view --root` follows the existing standalone path with an empty alias map. `/api/index` adds only optional ephemeral `alias`; canonical handles, logical IDs, artifacts, and provenance are unchanged. The React list displays alias first while detail views retain canonical identity.

Top-level help now groups `init`, `capture`, and `view` under Common workflow and all existing commands under Advanced. No `check` command was added.
