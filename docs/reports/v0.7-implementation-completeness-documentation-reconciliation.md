## 12. PROMPT 1–8 AUDITS

**Prompt 1 (external-reference foundation).** `ExternalReferenceArtifact`
family with deterministic, path-independent content identity
(`externalReferenceIdentity.ts`, SHA-256 over canonicalized semantic view,
never including the source file path — confirmed by source inspection),
provenance (`label`, never part of identity), PNG/JPEG/WebP detection from
header/magic bytes only (`EXTERNAL_REFERENCE_SUPPORTED_IMAGE_FORMATS`),
bounded size (`EXTERNAL_REFERENCE_MAX_IMAGE_BYTES` = 20,000,000) and
dimension (`[EXTERNAL_REFERENCE_MIN_DIMENSION_PX,
EXTERNAL_REFERENCE_MAX_DIMENSION_PX]` = `[1, 8192]`) bounds, `imported`/
`approved` two-state lifecycle, explicit forward-only supersession
(`--supersedes`, prior artifact never modified), immutable historical
manifests, `import-reference`/`approve-reference` CLI commands, no
automatic approval, and no conflation with `ObservationArtifact` (a wholly
separate artifact family/reader/writer). All confirmed present in
`src/domain/externalReference.ts`, `externalReferenceImage.ts`,
`externalReferenceIdentity.ts`, `src/artifacts/externalReferenceArtifact{Writer,Reader}.ts`,
and their unit tests. **Status: implemented, matches report.**

**Prompt 2 (reference regions).** Explicit region identity (`id` +
rectangle in reference-image pixel space, origin top-left), reusable
region-to-region geometry relationships, bounded maximum region count,
validation of malformed/duplicate/out-of-bounds regions, region content
(not file paths) participating in logical identity. Confirmed in
`src/domain/externalReferenceRegion*.ts` and `--regions-file` CLI support.
**Status: implemented, matches report.**

**Prompt 3 (requirements/adequacy).** Requirement categories
(`requested`/`expected-dependent`/`protected`/`preserved`; `unexpected`
never authorable), subjects (property/relationship/derived measurement),
tolerance model (`exact`/`absolute-reference-px`/`percent`, relationship
subjects must omit tolerance), reference-side requirement adequacy
(`adequate`/`partial`/`inadequate`). Confirmed in
`src/domain/externalReferenceRequirement*.ts`,
`externalReferenceAdequacy.ts`, and `--requirements-file` CLI support.
**Status: implemented, matches report.**

**Prompt 4 (applicability/compatibility).** Explicit, caller-declared
applicability (`viewport`, `theme`, `applicationState`,
`authenticatedState` restricted to literal `'authenticated'`/
`'unauthenticated'`), never inferred from image or DOM; reference/candidate
compatibility states (`comparable`/`comparable-with-warnings`/
`incomparable`), reusing/extending the v0.4 comparability model rather than
inventing a parallel one. Confirmed in `src/domain/explicitState.ts`,
`externalReferenceApplicability.ts`, `externalReferenceCompatibility.ts`,
and `--applicability-file`/`--state-file` CLI flags. **Status: implemented,
matches report.**

**Prompt 5 (region-to-target binding).** Explicit, never-inferred
reference-region ↔ runtime-target binding via `--bindings-file`; binding
outcomes remain conservative (bound/unbound/ambiguous-shaped, never
silently inferred from geometry or naming); runtime target identity is
carried verbatim, never becoming source ownership. Confirmed in
`src/domain/externalReferenceRuntimeBinding.ts`. **Status: implemented,
matches report.**

**Prompt 6 (fidelity evaluation).** `evaluateReferenceCandidateFidelity`
composes adequacy (Prompt 3) → compatibility (Prompt 4) → bindings (Prompt
5) → per-requirement pass/fail/unavailable evaluation, producing a
`not-evaluated`/`pass`/`fail` overall fidelity state; a blocked evaluation
(`not-evaluated`, due to inadequate reference or incompatible candidate) is
a distinct, legitimate outcome from a structural validation failure.
`evaluate-reference-fidelity` CLI command persists nothing (verified: no
artifact writer imported by its handler). Confirmed in
`src/domain/externalReferenceFidelity.ts` and
`src/application/referenceFidelityEvaluationService.ts`. **Status:
implemented, matches report.**

**Prompt 7 (bounded projection + v0.6 integration).**
`projectReferenceFidelity` and additive, backward-compatible extensions to
`boundedAgentContext.ts`/`boundedAgentContextIdentity.ts`/
`boundedAgentContextProjection.ts` (new optional trailing parameters,
omitted rather than defaulted to `null` when absent — confirmed by source
inspection of the identity-hash semantic view construction) integrate
Prompt 6's fidelity evidence into the existing bounded-context projection
without recomputing prior logic and without a new persisted artifact
family. **Status: implemented, matches report.**

**Prompt 8 (correction workflow).** `prepareReferenceCorrection` (pre-change
evidence → bounded `ReferenceCorrectionHandoff`, no raw image bytes, no full
`ObservationArtifact`, no source excerpt) and
`reviewReferenceCorrectionAttempt` (post-edit candidate → composed overall
result: `overallState = 'not-evaluated'` iff fidelity not-evaluated, else
`'pass'` iff fidelity `'pass'` AND v0.5 contract `'PASS'`, else `'fail'`),
both fail closed on an unapproved reference, both reject a
`reviewRequestId` that does not match its own recomputed inputs
(deterministic non-timestamp identity via `referenceCorrectionIdentity.ts`
— re-verified in this audit, including the identity-completeness fix from
the independent-judge review that now hashes actual `clauses` content, not
just baseline/contract labels). Proven end-to-end against real Chromium
(`tests/browser/referenceCorrectionWorkflow.test.ts`: success,
protected-regression, and multi-attempt correction-iteration cases). No new
CLI command and no new persisted artifact family — both confirmed
intentional, documented design decisions, not gaps. **Status: implemented,
matches report.**
