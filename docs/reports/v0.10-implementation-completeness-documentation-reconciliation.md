## 7. Viewer action and API inventory

The top-level Viewer modes are Evidence, Bounded context, and Visual changes.
Standalone `view --root` permits inspection only. Project-aware sessions may
save annotations, promote runtime intent, materialize reference intent,
approve an imported reference, create actual/reference workflows, activate,
run a check, restore acceptance, prepare a handoff, review, and record an
already-completed governance result.

The v0.10 routes are:

- `GET /api/visual-changes/:handle/view`
- `POST /api/visual-changes`
- `POST /api/visual-changes/:handle/activate`
- `POST /api/visual-changes/:handle/check`
- `POST /api/visual-changes/:handle/restore-acceptance`
- `POST /api/visual-changes/:handle/prepare-handoff`
- `POST /api/visual-changes/:handle/review`
- `POST /api/visual-changes/:handle/governance`
- `POST /api/annotations/:handle/start-visual-change`
- `POST /api/references/:handle/approve`
- `POST /api/references/:handle/start-visual-change`

They reuse exact Host/Origin, memory-only token, JSON content type, compression,
body-bound, closed-shape, containment, serialization, and no-store controls.
