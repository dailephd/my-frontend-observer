# Node validation and CI policy

**Local (development and readiness):** Use the latest stable Node.js release and run `npm ci` followed by `npm run validate:local`. The script verifies the exact running version against the official [Node.js release index](https://nodejs.org/dist/index.json) before executing typecheck, lint, unit tests, browser tests, build, and documentation checks. It does not install Node and fails closed when the release index cannot be reached. During corrections run focused suites rather than repeatedly executing the full local gate.

**Hosted:** [pre-release-readiness.yml](../.github/workflows/pre-release-readiness.yml) uses **Node 24**. It runs the full unit and browser suites once in the Linux candidate job. The previously separate `test:security` step repeated tests already exercised by those two suites; security coverage is retained through the normal unit and browser jobs. The cross-platform installed-tarball smoke and cross-platform tutorial-readiness jobs are **different integration responsibilities**, so they remain on Ubuntu, macOS, and Windows. Do not substitute their installed-browser evidence with unit-test results.

Avoid redundant candidate builds and double workflows for the same branch: automatic pushes to `validation/**` trigger candidate readiness, release PRs targeting `master` trigger PR readiness, and `workflow_dispatch` remains available for explicit runs. Release-branch push duplicates were removed; release PR coverage is unchanged. GitHub's supported baseline is Node 24; latest-stable compatibility is a local responsibility, not a duplicated hosted Node matrix.
